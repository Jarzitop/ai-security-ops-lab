# Architecture v1

Status: **proposed — cloud provider / student credits pending confirmation**

## Design goal

Build a SOC lab that fits an 8 GB Windows laptop without running the Wazuh central stack locally.

## Logical architecture

```text
                           Internet
                              |
                   +----------------------+
                   | Remote Wazuh server  |
                   | Linux                |
                   | Server + Indexer +   |
                   | Dashboard            |
                   +----------+-----------+
                              |
              Wazuh agent telemetry / enrollment
                              |
          +-------------------+-------------------+
          |                                       |
+---------+----------+                  +---------+----------+
| Windows 11 host    |                  | Future Linux VM    |
| Sysmon             |                  | Ubuntu Server      |
| Windows Event Logs |                  | Wazuh Agent        |
| Wazuh Agent        |                  | SSH/auth logs      |
+--------------------+                  +--------------------+
                                                   ^
                                                   |
                                      controlled local traffic
                                                   |
                                          +--------+-------+
                                          | Kali Linux VM  |
                                          | existing VM    |
                                          +----------------+
```

## Resource strategy

### Host — Windows 11

Use as the first endpoint for **safe telemetry generation only**.

Planned:
- Sysmon;
- Windows Event Logs;
- Wazuh Agent.

Do not perform destructive or high-risk simulations on the physical host.

### Kali VM

Existing VM.

Role:
- controlled network activity;
- reconnaissance against lab-only VMs;
- later attack simulation where explicitly authorized.

Run only when required.

### Future Ubuntu Server VM

Proposed initial allocation:
- 1–2 vCPU;
- 1.5–2 GB RAM;
- 15–20 GB disk.

Role:
- isolated Linux endpoint;
- SSH/authentication scenarios;
- sudo/process/service telemetry;
- controlled interaction with Kali.

### Remote Wazuh central components

Run Wazuh Server, Indexer, and Dashboard outside the laptop.

Current Wazuh quickstart recommendation for 1–25 agents:
- 4 vCPU;
- 8 GiB RAM;
- 50 GB storage.

Cloud/student-credit option is preferred only if cost controls are acceptable.

## VM concurrency

With 7.84 GB physical RAM:

- Windows host + Kali: acceptable for short lab sessions if Kali remains small.
- Windows host + lightweight Ubuntu Server: acceptable.
- Windows host + Kali + lightweight Ubuntu Server: possible but likely constrained; test before relying on it.
- Local Wazuh all-in-one + endpoint VMs: rejected.
- Windows lab VM may be added later, but should replace rather than join other heavy VMs during a session.

## Networking

Initial local design:
- VMware NAT for Internet access.
- Kali and victim VMs must be able to communicate within the controlled virtual network.
- Remote Wazuh access should be restricted to the user's source IP or a private overlay where practical.
- Do not expose unnecessary management ports publicly.

Exact ports and cloud firewall rules will be documented only after the remote Wazuh deployment method is selected.
