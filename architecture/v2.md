# Architecture v2 — AI-Augmented Security Operations Lab

Status: **PLANNED / PARTIALLY IMPLEMENTED**

This is the active target architecture. Components are not considered operational until individually validated.

## Design goals

1. Produce real endpoint telemetry.
2. Build and validate detections against known scenarios.
3. Conduct evidence-based SOC investigations.
4. Build an AI assistant that operates on retrieved evidence rather than free-form assumptions.
5. Evaluate the assistant against independent ground truth.
6. Keep cloud cost and attack surface small.

## Component placement

### Physical Windows 11 host

Role:
- safe endpoint telemetry source;
- Windows Event Logs;
- Sysmon;
- Wazuh Agent.

Constraint:
- no destructive or high-risk simulation.

### Azure

Current validated state:
- Azure for Students access works through Azure CLI;
- resource group `rg-soc-detection-lab` exists in `East US`.

Planned next component:
- Ubuntu VM for Wazuh central services.

The VM has not yet been created.

### Kali VM

Existing local VM.

Planned role:
- authorized traffic generation;
- controlled adversary simulation against isolated lab targets.

### Future Linux target

A lightweight isolated Linux endpoint may be added for SSH/authentication/sudo/process scenarios.

It is not yet implemented.

## AI layer

The AI component is downstream of security evidence.

Planned pipeline:

```text
Wazuh alert/export
      ↓
parser
      ↓
normalized event schema
      ↓
related-event correlation
      ↓
context construction
      ↓
optional knowledge retrieval
      ↓
LLM
      ↓
validated structured output
```

The model must distinguish:
- facts supported by event evidence;
- inferences;
- missing information;
- recommended next actions.

The initial system is read-only and cannot perform autonomous remediation.

## Trust boundaries

Untrusted:
- endpoint logs;
- process names;
- command lines;
- usernames;
- filenames;
- network-sourced content;
- retrieved documents that have not been curated.

Trusted control plane:
- application/system prompts;
- schema validators;
- evaluation ground truth;
- manually reviewed project configuration.

This distinction is important for later indirect prompt-injection testing.

## Network principles

- expose only ports required for the current phase;
- restrict management access by source where practical;
- do not commit public IPs or credentials;
- isolate higher-risk simulations from the physical host;
- document actual firewall/NSG rules after deployment.

## Cost principles

- use Azure compute only when needed;
- configure auto-shutdown;
- deallocate VMs after lab sessions;
- keep disks and managed services minimal;
- defer Sentinel ingestion until the Wazuh workflow is already validated;
- record observed cost rather than relying only on estimates.
